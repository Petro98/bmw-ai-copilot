# Plan 3 — Voice on the phone (phase 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. When this plan runs inside a parallel wave (see `2026-11-13-00-execution-map.md`), do not run `git add`/`git commit` yourself: report the files you changed and the orchestrator commits them.

**Goal:** The driver taps one large button on the phone, asks in Ukrainian, and hears the answer through the car's speakers — using only the browser's own free speech features.

**Architecture:** Speech lives entirely in the companion behind two small adapter interfaces (recogniser, speaker) with browser implementations; a pure state machine drives the talk screen. The backend's answer stream additionally emits whole sentences for the spoken style so speech can start before the answer is complete. Nothing runs on the head unit.

**Tech Stack:** Angular 22 (the companion of Plan 1), Web Speech API (`SpeechRecognition`, `speechSynthesis`) in Chrome on Android, Screen Wake Lock API, Angular service worker for installability; Fastify route change in the backend.

**Spec:** `docs/superpowers/specs/2026-11-13-bmw-ai-copilot-design.md` (§2, §8). Builds on Plan 1 Tasks 13–15 (`POST /api/ask/stream`, `AskService`, the assistant page). Design: `docs/design/mockups/PhoneTalk.dc.html`, `docs/design/README.md`.

## Global Constraints

- **No always-on listening.** Recognition starts only from a tap and ends with the result, a second tap, or 10 seconds without a result. There is no wake word in this plan.
- **Free path first.** Only browser speech is implemented. The adapter interfaces must allow a cloud recogniser or speaker to be added later without touching the talk screen.
- The phone speaks **only answers to questions the driver just asked**; it never speaks on its own.
- The microphone is closed while the phone is speaking.
- Language `uk-UA` for recognition and speech. Interface copy Ukrainian per `docs/design/README.md`.
- Questions are sent with `style: 'spoken'`, `source: 'voice'`.
- While the car is moving the screen shows the button, the state and the short answer — no text field, no lists.
- Nothing in this plan runs on, or sends audio to, the head unit.

## Review Focus

1. **A browser without speech** (no `SpeechRecognition`, or no Ukrainian voice): a plain message says what is missing, the text path keeps working, nothing throws. Tests: Tasks 2, 3.
2. **Microphone permission refused or withdrawn**: one clear instruction, back to idle, the next tap tries again. Tests: Task 3.
3. **A tap while thinking or speaking**: speech and the request stop at once, no overlapping audio, no stuck state. Tests: Task 3.
4. **The network drops mid-answer**: speech stops after the sentence in progress, the error is shown, the state returns to idle. Tests: Task 3.
5. **Awkward text for the splitter**: decimals, abbreviations, an answer with no final full stop, a 600-character run without punctuation — every character is spoken once, in order. Tests: Task 1.

**Interfaces:**
- Consumes: `AskStreamEvent` (`sentence` variant already in the contract), `AssistantService.ask(request, onDelta)`.
- Produces:
```ts
export const MIN_SENTENCE_CHARS = 12;
export const MAX_SENTENCE_CHARS = 300;
export class SentenceSplitter {
  push(delta: string): string[];     // sentences completed by this delta, trimmed
  flush(): string[];                 // whatever is left, as one or more sentences
}
```
Rules: a sentence ends at `.`, `!`, `?` or `…` when followed by whitespace (or at `flush`). Not an end: a `.` or `,` between two digits (`2,3`, `12.5`); a `.` right after one of `напр`, `тис`, `хв`, `год`, `км`, `див`, `тощо`, `ін`, `т`, `д`, `р`. A fragment shorter than `MIN_SENTENCE_CHARS` is held and joined with the next one. Text longer than `MAX_SENTENCE_CHARS` without an end is cut at the last space before the limit. Concatenating everything returned by `push` and `flush`, separated by single spaces, reproduces the input with whitespace normalised.
Route: for `style === 'spoken'`, `POST /api/ask/stream` sends each completed sentence as `event: sentence` in addition to the `delta` events, flushes before `done`; for `style === 'full'` it sends no `sentence` events.

- Test: `apps/companion/src/app/speech/{browser-recognizer.spec.ts,browser-speaker.spec.ts}`

**Interfaces — Produces:**
```ts
export const SPEECH_LANG = 'uk-UA';
export const LISTEN_TIMEOUT_MS = 10_000;
export type RecognizerErrorCode = 'unsupported' | 'not-allowed' | 'no-speech' | 'network' | 'aborted' | 'other';
export type RecognizerEvent =
  | { type: 'partial'; text: string } | { type: 'final'; text: string }
  | { type: 'error'; code: RecognizerErrorCode } | { type: 'end' };
export interface SpeechRecognizer {
  isSupported(): boolean;
  start(onEvent: (event: RecognizerEvent) => void): void;   // must be called from a user gesture
  stop(): void;                                             // finish and deliver what was heard
  abort(): void;                                            // discard
}
export interface SpeechSpeaker {
  isSupported(): boolean;
  hasVoice(): boolean;                                      // a voice whose language starts with 'uk'
  prime(): void;                                            // call inside the tap so later speech is allowed
  speak(text: string): Promise<void>;                       // queues; resolves when this utterance ends or is cancelled
  cancel(): void;
  speaking(): boolean;
}
export const SPEECH_RECOGNIZER: InjectionToken<SpeechRecognizer>;
export const SPEECH_SPEAKER: InjectionToken<SpeechSpeaker>;
```
Decisions: `BrowserSpeechRecognizer` uses `window.SpeechRecognition ?? window.webkitSpeechRecognition` with `lang = SPEECH_LANG`, `continuous = false`, `interimResults = true`, `maxAlternatives = 1`; it stops itself after `LISTEN_TIMEOUT_MS`; it always ends with exactly one `end` event; browser error names map as `not-allowed`/`service-not-allowed` → `not-allowed`, `no-speech` → `no-speech`, `network` → `network`, `aborted` → `aborted`, anything else → `other`. `BrowserSpeechSpeaker` uses `speechSynthesis`, waits for `voiceschanged` before answering `hasVoice()` truthfully, speaks one utterance per call with the Ukrainian voice and `lang = SPEECH_LANG`, and `prime()` speaks an empty utterance. Both take the `window` object through their constructor so tests pass a fake.

### Task 3: Talk flow on the assistant screen (`companion`)

**Files:**
- Create: `apps/companion/src/app/features/assistant/{talk.machine.ts,talk.controller.ts,wake-lock.ts}`
- Modify: `apps/companion/src/app/features/assistant/assistant.page.{ts,html,css}`, `apps/companion/src/app/core/ask.service.ts` (deliver `sentence` events to an optional callback; accept `source`)
- Test: `apps/companion/src/app/features/assistant/{talk.machine.spec.ts,talk.controller.spec.ts,assistant.page.voice.spec.ts}`

**Interfaces:**
- Consumes: the adapters of Task 2; `AskService`; `sentence` events of Task 1.
- Produces:
```ts
export type TalkState = 'idle' | 'listening' | 'thinking' | 'speaking';
export interface TalkModel { state: TalkState; transcript: string; message: string | null; pendingSpeech: number; answerDone: boolean }
export type TalkInput =
  | { type: 'tap' } | { type: 'stop' }
  | { type: 'partial'; text: string } | { type: 'final'; text: string }
  | { type: 'rec-error'; code: RecognizerErrorCode } | { type: 'rec-end' }
  | { type: 'sentence'; text: string } | { type: 'answer-done' } | { type: 'answer-error'; message: string }
  | { type: 'speech-ended' };
export type TalkEffect =
  | { type: 'prime-speaker' } | { type: 'start-listening' } | { type: 'stop-listening' } | { type: 'abort-listening' }
  | { type: 'ask'; text: string } | { type: 'cancel-ask' } | { type: 'speak'; text: string } | { type: 'cancel-speech' };
export const INITIAL_TALK: TalkModel;
export function reduce(model: TalkModel, input: TalkInput): { model: TalkModel; effects: TalkEffect[] };
```
Transitions:
- `idle` + `tap` → `listening`; effects `prime-speaker`, `start-listening`; transcript and message cleared.
- `listening` + `partial` → transcript updated. `listening` + `tap` → effect `stop-listening` (state stays until the result arrives).
- `listening` + `final` with non-blank text → `thinking`; effect `ask`. `final` blank, or `rec-end` without a final → `idle` with message «Не почув запитання. Натисніть і скажіть ще раз.»
- `listening` + `rec-error`: `not-allowed` → `idle`, «Дозвольте доступ до мікрофона для цієї сторінки в налаштуваннях браузера.»; `network` → «Немає мережі для розпізнавання мовлення.»; `no-speech` → as blank; `unsupported` → «Цей браузер не розпізнає мовлення. Напишіть запитання текстом.»; others → «Не вдалося розпізнати. Спробуйте ще раз.»
- `thinking` or `speaking` + `sentence` → `speaking`; effect `speak`; `pendingSpeech + 1`.
- `speech-ended` → `pendingSpeech − 1`; when it reaches 0 and `answerDone` → `idle`.
- `answer-done` → `answerDone = true`; if `pendingSpeech` is 0 → `idle`.
- `answer-error` → effects `cancel-speech`; `idle` with the message.
- `thinking` or `speaking` + `tap` or `stop` → effects `cancel-ask`, `cancel-speech`; `idle`.
- Any input not listed for a state leaves the model unchanged with no effects.
`talk.controller.ts` runs the effects against the adapters and `AskService` and feeds their events back into `reduce`. With no Ukrainian voice the controller skips `speak` effects (reporting `speech-ended` at once) and the page shows «На цьому телефоні немає українського голосу. Відповідь показано текстом.» The wake lock is requested while the page is visible and re-requested on `visibilitychange`; a browser without it is silently ignored.
Screen (per `PhoneTalk.dc.html`): the 176 px round button with `aria-label` «Говорити» in idle and «Зупинити» otherwise; a state line under it — «Натисніть і говоріть», «Слухаю…», «Думаю…», «Відповідаю…»; the level-meter bars are shown only in `listening` and `speaking` (the one permitted animation, phone only); the transcript appears as the question; the answer text grows as before. The text field and chips of Plan 1 remain below, hidden while moving.
