# Plan 2 — Car app and car link (phases 2 and 4, built and tested off the car) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. When this plan runs inside a parallel wave (see `2026-11-13-00-execution-map.md`), do not run `git add`/`git commit` yourself: report the files you changed and the orchestrator commits them.

**Goal:** A Store-installable, read-only, autostart head-unit app that reads passive signals, runs the shared rules, shows BMW's small pop-up and a Ukrainian screen, and exchanges compact data with the backend — complete and verified as far as is possible without the car.

**Architecture:** TypeScript in `car/src`, bundled by esbuild into one ES2017 CommonJS file that the vendored MIT app kit loads on the head unit's Node 8. Our modules are pure and injected with the kit's APIs, so they are unit-tested on Node 22 and smoke-tested on Node 8; the kit's offline preview renders the screens to PNG. The backend gains device authentication and a provider fed by the car.

**Tech Stack:** TypeScript → esbuild (`target: es2017`, CommonJS), vendored app kit (`JustAnotherPU/mgu-apps` `kit/`, MIT, itself derived from `cauliflowermossgrape/idrive7-apps`, MIT), Python 3 for the kit's build and preview tools, Vitest, Node 8.16.2 for smoke tests, Fastify for the backend part.

**Spec:** `docs/superpowers/specs/2026-11-13-bmw-ai-copilot-design.md` (§2, §4, §6.4, §7, §9, §12). Contracts this plan builds on: Plan 1 Task 1 (`vehicle-core`, `event-engine`, `shared`). Design: `docs/design/README.md`, `docs/design/mockups/{Main,AssistantMoving,Sensors,Alerts,Popup}.dc.html`. Research record: `.research/reports/{lifecycle,telemetry,footprint,store,ui}.md`; pinned reference code under `.research/repos/` and `.research/jap-fetch/`.

## Global Constraints

- **Nothing in this plan installs, copies or sends anything to the car.** Every on-car step is written down for the owner in `docs/CAR_INSTALL.md` and performed by him.
- **Read-only.** The app declares no signal with the write flag, never calls the kit's `signals.set`, never calls a method on a vehicle interface, never sends a diagnostic request (the diagnostic gate of Task 5 ships disabled and has no caller), never references `WakeUpOnDemand`, `WodControl` or `RegisterShutdownClient`.
- **Never crash, never exit.** No `process.exit`. Every timer callback, signal handler and promise chain goes through one `safe()` wrapper that logs once and carries on. No unbounded array, map or buffer.
- **Head-unit runtime:** Node 8.16.2, CommonJS. The bundle is one file, ES2017 syntax, no dependency that needs a newer runtime, no `fetch`, no global `URL`, no `fs.rmSync`, no recursive `mkdir`.
- **Budgets (spec §9):** one process; `memoryKB` 131072; `cpuLimit` 30; one 1 Hz tick while the ignition is on, zero timers when parked; the screen is drawn only while visible and only when something changed; at most one small state write per drive; log at most a few lines per drive; network at most one request a minute while driving and none when parked.
- **No secrets and no car identity in the repository:** no backend address, no device secret, no vehicle identification number, no file copied from a head unit. BMW's SDK is never vendored.
- **Licences:** copy only MIT code, keep its notices, list every vendored file's origin and every local change in `car/kit/VENDORED.md`. GPL projects (`idrive7-custom-apps`, `mgu-store`, renderer and emulator sources) are read for behaviour only.
- **Kit APIs are read from the vendored source, not from memory or from this plan's prose.** Where this plan names a kit call, open the file it cites and confirm the signature before using it.
- Interface copy is Ukrainian per `docs/design/README.md`; code and docs are English.
- A wrong head-unit clock is treated as an error state shown to the driver («Годинник головного блока неправильний»), never worked around by weakening certificate checks. (The clock-tolerant verification the spec mentions is deferred until the owner's car check shows the clock is actually wrong.)

## Review Focus

1. **The car goes quiet** — signals stop without a state change (the kit warns that a parked car sends nothing for minutes, and that some fields never notify): readings age instead of freezing as fresh, the power gate falls asleep after its idle fallback, and no timer keeps running. Tests: Tasks 2, 3.
2. **The uplink disappears mid-drive** — no lease, DNS failure, timeout, HTTP 5xx, the phone leaving the car: the buffer stays bounded, nothing retries in a loop, alerts still pop up locally, and sending resumes on its own. Tests: Tasks 4, 6.
3. **A signal the firmware does not have, or a struct shaped differently than the fixture** — a missing field becomes `not-on-this-vehicle` or `invalid-value`, never an exception and never a zero. Tests: Task 2.
4. **Tile tap on a running background process, and a restart in the middle of a drive** — the app rebuilds from its small state file; cooldown memory survives so an alert is not repeated; a corrupt or missing state file starts clean. Tests: Tasks 4, 9.
5. **Text the head unit cannot draw** — a Check Control text or an answer containing characters outside the baked atlas (or the pop-up widget refusing Cyrillic): the text is still legible (fallback transliteration for the pop-up, a visible placeholder glyph on the canvas), never blank and never a crash. Tests: Tasks 4, 8.

- Produces:
```ts
export interface SignalsApi { watch(iface: string, instance: string | undefined, handlers: Record<string, (value: unknown) => void>, log: Log, opts?: { pollMs?: number }): Promise<unknown> }
export function conditionFromRaw(raw: unknown): VehicleCondition | null;   // names or numbers: 1,2 → parked; 3 → standby; 5 → living; 7 → ignition-on; 8 → starting; 10 → driving; 12 → stopping; else null
export function applyRaw(snapshot: VehicleSnapshot, iface: string, field: string, value: unknown, now: number): void;   // mutates in place, assign-only
export interface BmwProviderOptions { signals: SignalsApi; clock: Clock; log: Log; missingInterfaces: string[]; staleAfterMs?: number }   // default 300_000
export class BmwMguVehicleDataProvider implements VehicleDataProvider {
  constructor(options: BmwProviderOptions);
  refresh(): VehicleSnapshot;      // called by the 1 Hz tick: stamps takenAt, marks old readings stale, notifies listeners if anything changed
}
```
Decisions:
- One `watch` per interface carrying all its fields; handlers only call `applyRaw` (no allocation beyond the reading, no logging, no I/O). Listeners are notified from `refresh()`, never from a signal handler.
- Polled interfaces (`transport: 'polled'` in the catalogue: fuel/range/odometer, tyres) are watched with `pollMs: 10000`.
- Interfaces listed in `missingInterfaces` (the kit writes what the unit's firmware lacks; read the kit to see where) yield `unavailable('not-on-this-vehicle')` for their readings; they are declared optional in `app.json` the way the kit supports (`"_optional"`), so a missing one cannot make the installer refuse the app. Essential, never optional: engine speed, vehicle speed, vehicle condition.
- A value that decodes to `null` → `unavailable('invalid-value')`. A reading not refreshed for `staleAfterMs` → `unavailable('stale')`, except those that legitimately change rarely (odometer, service items, Check Control), which keep their value and their original `at`.
- Tyre pressure arrives in the car's display unit (`unitOfMeasurementAirPressure`: 1 bar, 2 kPa, 3 psi). Convert kPa (÷100) and psi (×0.0689476) to bar and store `unit: 'bar'`; with the unit unknown store the raw-scaled value with `unit: null`.
- Check Control: build `CheckControlMessage[]` from the master list (id, active state) joined with the cluster list's text and colour; colour red → `critical`, yellow → `warning`, anything else known → `info`, unknown → `warning`; `text: null` when no text arrived. Service items from the cluster's service list: colour red → `overdue`, yellow/orange → `due-soon`, green → `ok`. Member names and enum spellings come from `.research/reports/telemetry.md` F6 and F13 and the files they cite — confirm them there; where the report says a structure is undocumented, walk it defensively and return `unavailable('invalid-value')` on anything unexpected.
- Diagnostic-only readings are always `unavailable('diagnostics-disabled')`.
- `raw-signals.json`: raw structs as the car sends them, adapted from the MIT demo feed in `.research/repos/idrive7-apps@4a8deb7/apps/live_data/signals.js` (`demo()`), with a header comment crediting it.

### Task 3: Power gate

**Files:**
- Create: `car/src/power/power-gate.ts`
- Test: `car/src/power/power-gate.test.ts`

**Interfaces:**
- Consumes: `VehicleSnapshot`, `Clock`.
- Produces:
```ts
export type PowerState = 'asleep' | 'awake' | 'driving';
export const IDLE_FALLBACK_MS = 900_000;           // 15 min, the kit's Ambient config convention
export class PowerGate {
  constructor(options: { clock: Clock; idleFallbackMs?: number });
  update(snapshot: VehicleSnapshot): PowerState;    // call on every tick and on every condition change
  state(): PowerState;
  onChange(listener: (next: PowerState, previous: PowerState) => void): () => void;
}
```
Rules: condition `parked` or `standby` → `asleep`; `living`, `ignition-on`, `starting`, `stopping` → `awake`; `driving` → `driving`. Condition unavailable: `driving` while speed is available and above `MOVING_ABOVE_KMH`; otherwise `awake` until `idleFallbackMs` has passed since the last time any reading's `at` advanced, then `asleep`. The initial state is `awake`. What the states mean for the rest of the app (wired in Task 9): `asleep` → no timer at all, no network, connections closed, state file written once; `awake` → 1 Hz tick, network only for an alert or a question; `driving` → 1 Hz tick and the once-a-minute snapshot upload.

```ts
export class DiagBlockedError extends Error { constructor(readonly reason: string) }
export const FUNCTIONAL_ADDRESS = 0xdf;
export function assertReadOnly(target: number, request: ReadonlyArray<number>): void;      // throws DiagBlockedError
export function diagAllowedNow(snapshot: VehicleSnapshot): { allowed: boolean; reason: string | null };

Allow-list (everything else throws): to one unit (target ≠ `0xDF`): `0x22` followed by 1–8 two-byte identifiers; `0x01` or `0x09` with exactly one byte. **Nothing in this plan constructs a `ReadOnlyDiagGate` with a real transport.** It exists so that the allow-list is reviewed and tested before any diagnostic feature is proposed to the owner.

export class RingBuffer<T> { constructor(capacity: number); push(item: T): void; drain(max: number): T[]; size(): number }   // drops the oldest when full
export type UplinkErrorKind = 'offline' | 'dns' | 'timeout' | 'clock' | 'tls' | 'unauthorized' | 'client-error' | 'server-error';
export class UplinkError extends Error { constructor(readonly kind: UplinkErrorKind, message: string) }
export interface HttpsClientOptions { baseUrl: string; lease: () => Lease; timeoutMs?: number; extraCaPem?: string[]; log: Log }   // timeout default 15000
export class HttpsClient { constructor(o: HttpsClientOptions); request<T>(method: 'GET' | 'POST', path: string, body: unknown, bearer: string): Promise<T>; close(): void }
export type LinkStatus = 'unpaired' | 'offline' | 'clock' | 'error' | 'ok';
export class UplinkClient {
  constructor(o: { http: HttpsClient; device: () => { id: string; secret: string } | null; clock: Clock; log: Log; sendIntervalMs?: number });   // default 60_000
  recordSnapshot(snapshot: VehicleSnapshot): void;        // into a RingBuffer of 240
  onTick(power: PowerState): void;                        // driving + interval elapsed + online → send one batch (≤ 60); otherwise nothing
  sendAlerts(events: AlertEvent[]): void;                 // at once when online; when not, kept (bounded, 20) for the next successful send
  ask(text: string, style: AskStyle): Promise<DialogTurn>;
  fetchConfig(): Promise<CarConfigResponse>;
  pollDialog(afterTurnId: string | null): Promise<DialogTurn[]>;   // one GET /car/v1/dialog; the caller decides when to call again
  status(): LinkStatus;
  close(): void;
}
```
Decisions:
- Node 8 `https.request` with one keep-alive agent (`maxSockets: 1`), a `lookup` that resolves through the lease's DNS servers (results cached 5 minutes, at most 32 names, each lookup raced against a 10 s timer), normal certificate verification, optional extra CA PEMs.
- Error mapping: no lease or `EHOSTUNREACH`/`ENETUNREACH` → `offline`; resolver failure → `dns`; timer → `timeout`; `CERT_NOT_YET_VALID` / `CERT_HAS_EXPIRED` → `clock`; other TLS errors → `tls`; 401/403 → `unauthorized`; other 4xx → `client-error`; 5xx → `server-error`.
- Retry policy: none inside a request. A failed batch goes back to the front of the buffer and is tried again at the next interval; after an `unauthorized` or `client-error` nothing is sent until the device or configuration changes.
- The client owns no timer: it acts only from `onTick` and from explicit calls, so a sleeping gate means a silent uplink. `close()` destroys the agent's sockets.
- Request bodies are JSON without indentation; snapshots are sent as they are.
